# CDP途中停止 改善案（2026-11-02）

## 報告
レビュー処理の途中で「CDPエラー」で止まった。エラー文・実回答JSON・ログは入手できていない。
リポジトリ内にもランタイムログは無いため、コードの経路から原因候補を絞った。

## 原因候補（可能性の高い順）

1. **送信前フェーズの CDP 例外がそのままパケット失敗になる**
   `Invoke-KoseiCopilotReviewRequest` で回答待機ループに入る前の処理
   （新規チャット・`Page.navigate`・モデル選択・添付・ベースライン取得・入力）は CDP 例外を捕まえていない。
   `Execution context was destroyed` / `CDP応答タイムアウト` / `CDP WebSocket受信失敗` が一度出るだけで、
   種別の付かない例外になって `Invoke-KoseiPacket` に届き、パケットは `error`。
   ReviewJob の自動再試行（新規チャット・分割）は**構造化された回答結果**にしか効かないため、
   再試行されないまま段階の境目で失敗扱いになり、ジョブ全体が「一部のパケットが失敗しました」で止まる。
2. **ターゲット消失・Edge 再起動で `cdp_reconnect_required` → アプリ再起動待ち**
   回答待機中の再接続は「同じターゲットIDへ」しか試さない。窓が閉じた・Edge が落ちて
   `Start-KoseiCopilotEdge` が別プロセスを起動した場合はIDが変わるので必ず失敗し、2回で
   `cdp_reconnect_required` になる。ジョブは入力を保持して `error` で終わり、**アプリを再起動するまで再開しない**
   （利用者からは「途中で止まった」に見える半死状態）。
3. **並列ワーカーの窓が死ぬと、そのワーカーが残りパケットを次々に失敗させる**
   ワーカーは死んだ `$Page` を握ったままキューから次のパケットを取り、各パケットが即座に CDP 例外で `error` になる。
4. **受信タイムアウト後のソケット中断が分かりにくいエラー文になる**
   .NET の `ClientWebSocket` は `ReceiveAsync` を取り消すとソケットが `Aborted` になる。
   `Invoke-KoseiCdpOnSocket` は取り消し後も同じソケットで受信を続けるため、本来の「CDP応答タイムアウト」ではなく
   `The WebSocket is in an invalid state ('Aborted')` という CDP 受信失敗として出る。
5. **エラー表示が生の例外文**
   カードには `CDP WebSocket受信失敗: …` が200字で切られて出るだけで、何が起きて何をすればよいかが分からない。

## 修正方針

- **CDP 層（CopilotClient.ps1）**
  - ソケットが Open でない／受信が取り消された時点で、種別付き例外（`cdp_transport`）で即座に止める。
    閉じたソケットの再利用をやめ、「応答タイムアウト」「ソケット切断」を区別した文にする。
  - `Get-KoseiCdpFailureKind` を追加し、種別付き例外と、既存の生 CDP 例外文（`Execution context was destroyed`,
    `No target with given id`, `CDP応答タイムアウト` など）を `cdp_transport` に分類する。ページ側JSの例外や送信先検査は対象外。
  - `Invoke-KoseiCopilotReviewRequest` は CDP 由来の失敗を、フェーズ名・送信済みかどうか付きの `cdp_transport` 例外に包み直す。
  - `Restore-KoseiCopilotPage` を追加。Edge/DevTools を起こし直し、同じターゲットが生きていて実際に読めればそれを使い、
    消えていれば新しい窓を作って **同じページオブジェクトを書き換える**（後続パケット・後始末も新しい窓を見る）。
- **ジョブ層（ReviewJob.ps1）**
  - 新規チャットで送るリクエスト（初回・再試行・分割・全体再試行）は、`cdp_transport` / `cdp_reconnect_required` を受けたら
    ページを復旧して **最大2回まで同じリクエストをやり直す**（中止要求は待機中も尊重）。
  - 回数を使い切ったら `cdp_reconnect_required`（入力を保持し、次回起動で未完了パケットだけ再開）へ明示的に倒し、
    そのワーカーは止める（死んだ窓で残りを失敗させない）。並列時の残りは他ワーカーが引き取る。
  - 多パスの追撃（Reuse）で CDP が切れた場合は、チャットの文脈が失われ得るので再送せず、ページだけ復旧して
    残りの追撃を「要確認」として打ち切る（パケット全体は warning、ジョブは継続）。
  - 利用者向け文言: パケット・ジョブのエラーに「Copilot（Edge）との接続が切れた」「自動で再接続を試みた回数」
    「次に何をすればよいか」を出す。
- **黙って握りつぶさない**: 復旧のたびに WARN、諦めたときは ERROR をログへ残す。回数は有限。

## テスト（ライブ Edge 不要）
- `Test-CdpMidrunRecovery.ps1` を追加し `test-manifest.json`（fast）へ登録。
  - 閉じた／中断したソケットで種別付き例外になり、受信を重ねないこと
  - 生 CDP 例外文の分類（送信先検査・JS 例外は分類しない）
  - 送信前フェーズの CDP 例外が `cdp_transport`（phase・sent 付き）になること
  - `Restore-KoseiCopilotPage`: 生きているターゲットは再利用、消えたターゲットは新しい窓に差し替え（オブジェクトを書き換え）
  - `Invoke-KoseiPacket`: 1回目 CDP 失敗 → 復旧して成功、復旧を使い切ると `cdp_reconnect_required` で入力保持・ワーカー停止
- 既存の `Test-CopilotSendBoundary.ps1` / `Test-CopilotSession.ps1` / `Test-CopilotWindowCleanup.ps1` / `Test-JobRecovery.ps1` を回す。
