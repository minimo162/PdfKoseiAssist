## 0. 目的

今は、次の手順を踏まないと校正できない。

1. 起動 `.cmd` を実行する
2. ブラウザでUIが開くのを待つ
3. PDFを選び、比較資料を選ぶ
4. 「校正を開始」を押す
5. 完了を待つ
6. 「レポートZIPを書き出す」を押す

これを、**エクスプローラーでPDFを選んで右クリック →「送る」→「PDF校正アシストで校正」を選ぶだけ**で済むようにする。UIも黒い窓も出さずに、元PDFと同じフォルダへ結果のフォルダ（展開済みのレポート）を保存し、完了したらそのままレポートを開く。

### 起動方法の位置づけ

| 起動方法 | 位置づけ | 画面に出るもの |
|---|---|---|
| 右クリック →「送る」→「PDF校正アシストで校正」 | **正式な方法** | タスクトレイのアイコンと通知だけ。黒い窓もUIも出さない |
| `PDF校正アシスト起動.cmd` をダブルクリック | 従来どおり残す | 今と同じUI。画面で確認しながら校正したいとき用 |
| `PDF校正アシスト起動.cmd` にPDFをドロップ | 予備として残す | 「送る」と同じ（`.cmd` の窓が一瞬出るのは許容） |
| `PDF校正アシスト_初回セットアップ.cmd` | 最初に1回だけ | 案内のダイアログ（と、必要ならサインイン用の Edge） |

**配布フォルダの直下に置く起動用ファイルは、「起動」と「初回セットアップ」の `.cmd` 2つだけにする。** ドロップ専用の `.cmd` は作らない。既存の `PDF校正アシスト起動.vbs` は配布から外す（§3.8）。

```
PDF校正ツール\
  PDF校正アシスト_初回セットアップ.cmd   ← 最初に1回（新規）
  PDF校正アシスト起動.cmd                ← 従来どおり＋PDFのドロップも受け付ける
  はじめにお読みください.txt
  _app\
```

### 利用者から見た動き（完成形）

**最初に1回：**
1. `PDF校正アシスト_初回セットアップ.cmd` を実行する。
2. 「送る」メニューに登録される。
3. Copilot 用の Edge が開き、サインインしていなければ案内が出る。サインインが済むと自動で先へ進む。
4. 最後に次のダイアログが出て、終わる。
   > 準備ができました。英文PDFと日本語の原稿PDFを同じフォルダに置き、2つを選んで右クリック →「送る」→「PDF校正アシストで校正」を選んでください。Windows 11 では、右クリック →「その他のオプションを確認」の中に「送る」があります。

**毎回：**
1. 英文PDFと日本語の原稿PDFを**同じフォルダに置き**、Ctrl＋クリックで2つを選ぶ。英文だけで校正するなら1つを選ぶ。
2. 右クリック →「送る」→「PDF校正アシストで校正」を選ぶ。
3. タスクトレイにアイコンが出て、「校正を始めました：FY2027_Q1_en.pdf（比較資料あり）」と通知される。
   - アイコンにマウスを乗せると、進捗（例：「原稿との突き合わせ 3/4」）が見える。
   - 右クリックで「中止」と「Copilot画面を表示」を選べる。
4. 終わると「校正が終わりました：指摘 4件」と通知され、**Edge で指摘レポートが自動で開く**。トレイのアイコンは消える。
   - 同じフォルダに、結果のフォルダ `FY2027_Q1_en_校正結果` ができている。直下に見えるのは次の2つだけ（§3.10）。
     ```
     FY2027_Q1_en_校正結果\
       指摘レポートを開く.cmd   ← 開き直すときはこれ
       指摘レポート.html
       _data\                  （一時サーバー・PDF表示の部品・CSV・JSON・確認状況）
     ```
5. レポートで指摘を確認し、「確認済み」を付けていく。付けた印は、結果のフォルダ内の `_data\確認状況.json` に保存される（#170・§3.10）。
6. **あとで開き直すとき**は、結果のフォルダの「指摘レポートを開く.cmd」をダブルクリックする。黒い窓は出ず、Edge でレポートが開く。印は前回の続きから表示される。レポートのタブを閉じると、裏の一時サーバーも自動で終わる。
   - `指摘レポート.html` を直接ダブルクリックした場合は、レポートの代わりに「このファイルは『指摘レポートを開く.cmd』から開いてください」と大きく表示される（§3.10）。
7. **人に渡すとき**は、結果のフォルダを共有フォルダに置き、相手に「指摘レポートを開く.cmd」を実行してもらう。付けた印も一緒に見える。
   - メールで送る場合だけ、各自でフォルダをZIPにする。受け取った人がZIPの中から `.cmd` を直接実行すると、「ZIPを展開してから実行してください」と案内される。
8. エラーのときは、原因と次にやることを書いたダイアログが出る。

#### 結果をZIPではなくフォルダで出す理由
- ZIPのまま開こうとする人が多い。ZIPのままではレポートを開けず、毎回「展開 → `.cmd` を実行」が必要になる。
- 「確認済み」の印は展開したフォルダに保存される（#170）。ZIPで出すと、展開するたびに別のフォルダになり、印が引き継がれない。
- UIの書き出しも、ZIPではなくフォルダにする（§3.10）。

#### レポートを一時サーバー経由で開く理由（変えないこと）
- 社内環境では、共有フォルダ上の HTML をダブルクリックすると、Edge のポリシー（IEモードのサイト一覧）で **IE モードで開かれる**。IE モードでは PDF.js が動かず、レポートを表示できない。
- `http://127.0.0.1:<port>`（自分のPCの一時サーバー）で開けば IE モードにならないため、「指摘レポートを開く.cmd」→ 一時サーバー → Edge、という経路を維持する。
- 「HTMLファイル1つにして直接開く」方式は、この理由で採らない。

### 今回やらないこと（スコープ外）

- 別フォルダのPDFを組にする仕組み（同じフォルダに置く前提とする）
- 監視フォルダ
- 3文書以上の一括処理
- 元PDFへのコメント書き込み
- 再校正時の差分表示
- UI（`index.html` の画面）の見た目や操作の変更。例外は、自動実行用の入口の追加（§3.4）と、レポートの書き出しをフォルダ保存にする変更（§3.10）だけ
- 校正ロジック・プロンプト・マスキングの変更。**UIのボタンと同じ処理経路をそのまま使うこと**。別の処理経路を作ってはいけない

## 1. 設計方針（必ず守る）

1. **校正の中身はUIと同じ関数で動かす。**
   - PDFの抽出・マスキング・パケット作成・取込・除外判定・レポート生成は、すべて `app/_app/index.html` のJSにある。
   - PowerShell 側で書き直してはいけない。二重実装はすぐにずれる（`__koseiBenchmark` のコメントにある実測例を参照）。
2. **土台は既存の無人実行の仕組みにする。**
   - `app/_app/tools/Run-Benchmark.ps1` は、CDP でつながった Copilot 用 Edge にアプリ画面を開き、`window.__koseiBenchmark` の関数を呼んで校正を無人で最後まで回している。これを製品用に整理して流用する。
3. **黒い窓を出さない。**
   - 「送る」経路では、コンソールを表示しない。
   - 利用者への伝達は、タスクトレイのアイコン・通知（バルーン）・ダイアログ・エクスプローラーの表示だけで行う。
   - `Read-Host`、`pause`、コンソールへの案内の出力に頼る設計にしない。詳細はログファイルへ書く。
4. **ブラウザからサーバーへ、利用者のファイルパスを渡さない。**
   - サーバーは、ドロップされた任意のパスを読んだり、任意のパスへ書いたりしない。
   - ファイルの受け渡しは、ランチャーが作業フォルダへコピーした分と、そこへ書き出させた分だけにする（§3.3）。
5. **PowerShell 5.1、管理者権限なしで動くこと。** 追加のランタイム（node、Python など）は使わない。トレイやダイアログは .NET Framework の `System.Windows.Forms` で作る。
6. **既存の起動方法・UIの動作を変えない。** `PDF校正アシスト起動.cmd` を引数なしで実行したときの動作は、今と同じであること。
7. **アップデートで壊れないこと。**
   - 新版を同じフォルダに上書き展開しても、別フォルダに展開しても、「送る」が旧版を指したまま動いたり、リンク切れになったりしないこと。
   - 新旧の版が混ざって動くこともないこと（§3.5・§3.7）。

## 3. 詳細仕様

### 3.1 入口

#### 3.1.1 「送る」のショートカット（正式な入口）

- 作成先: `%APPDATA%\Microsoft\Windows\SendTo\PDF校正アシストで校正.lnk`（作成は §3.5 の初回セットアップが行う）
- リンク先（TargetPath）: `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`
- 引数（Arguments）: `-NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File "<appフォルダの絶対パス>\_app\Start-DropReview.ps1"`
- 作業フォルダ: `<appフォルダ>`
- 実行時の大きさ（WindowStyle）: 最小化（7）。起動の瞬間に窓がちらつくのを抑えるため。
- アイコン: 既定でよい。
- エクスプローラーは、選んだファイルのパスを引数の末尾に付け足して、**1回の起動にまとめて渡す**。`.cmd` を経由しないので、`&` `%` `^` `(` `)` を含むパスも壊れない。ランチャーは `$args`（または `param([Parameter(ValueFromRemainingArguments)]…)`）で受け取る。
- 右クリックメニューに直接項目を足す方法（`HKCU\Software\Classes\SystemFileAssociations\.pdf\shell`）は採らない。この方法では、2ファイルを選ぶと**ファイルごとに別プロセスで起動される**ため、英文と原稿を1組として渡せない。
- Windows 11 では、「送る」は右クリックの「その他のオプションを確認」（または Shift＋右クリック）の中にしか出ない。最初に出るメニューへ直接出すにはアプリのパッケージ化と署名が必要で、配布形態に合わないため対応しない。利用者向けの説明に明記するだけでよい（§3.6）。

#### 3.1.2 `app/PDF校正アシスト起動.cmd`（既存を変更・予備の入口）

- **引数が無い場合（ダブルクリック）は、今とまったく同じ動作にする。**
- 引数がある場合（PDFがドロップされた場合）は、`start "" powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File "%~dp0_app\Start-DropReview.ps1" %*` を実行し、**すぐに終了する**。`.cmd` の窓は一瞬で消える。
- 分岐は `if "%~1"=="" goto :normal` のように `goto` で書く。**`%*` を括弧のブロック `( … )` の中で展開しない**（パスに `)` があるとブロックが壊れる）。
- 既存の書式を守る。
  - UTF-8（BOMなし）、CRLF、先頭で `chcp 65001 >nul` を実行する。
  - 日本語の固定パスは書かない。
  - UNCパスに対応するため `pushd "%~dp0"` を使う。
- cmd の引数解釈の制約で、`&` `%` `^` を含むパスはドロップ経路では正しく渡らないことがある。これは予備の入口なので許容する。ランチャーがファイルを見つけられなかった場合は、ダイアログで「このパスはドロップでは渡せません。右クリックの『送る』から実行してください」と案内する。

### 3.2 `app/_app/Start-DropReview.ps1`（新規・ランチャー本体）

`Run-Benchmark.ps1` の次の部分を流用する。

- CDP の接続と、アプリのタブの取得・作成: `Get-AppPageWs`、`Target.createTarget`
- 評価の呼び出し: `Invoke-App`
- 表示状態の確認と前面化: `Show-AppTab`、`Get-CopilotVisibility`

ベンチマーク専用の検査（他の Copilot 利用の検出、直前30分のヘルス判定など）は持ち込まない。共通部分を `src/` の関数へ切り出すか複製するかは任せるが、**`Run-Benchmark.ps1` の挙動は変えないこと**。

#### 表示（トレイ・通知・ダイアログ）

- 共通関数は `src/DesktopUi.ps1` にまとめ、初回セットアップと共用する。
- **トレイアイコン**（`System.Windows.Forms.NotifyIcon`）
  - ツールチップ（`Text`）に「PDF校正アシスト：原稿との突き合わせ 3/4」のような現在の状況を出す。
    - **.NET Framework の `NotifyIcon.Text` は63文字が上限**で、超えると例外になる。必ず切り詰めること。
  - 右クリックメニュー：
    - 「状況：…」（押せない表示だけの項目）
    - 「Copilot画面を表示」（既存の `Show-KoseiCopilotEdgeWindow`）
    - 「中止」（確認ダイアログ「校正を中止しますか？」を出してから中止する）
  - ダブルクリックでは何もしない。アプリ画面は開かない。
- **通知**（`NotifyIcon.ShowBalloonTip`）: 開始・完了・利用者の操作が必要なときに出す。Windows の設定で通知が切られていても処理は続くので、**通知は補助**と位置づける。完了は、レポートが自動で開くことでも分かるようにする（手順8）。
- **ダイアログ**（`MessageBox`、または小さな `Form`）: エラーと、利用者の判断が必要な質問にだけ使う。常に最前面（TopMost）で出す。
- **メッセージループ**: トレイのメニューが2秒以内に反応すること。
  - CDP の呼び出しは数秒かかることがある。UIスレッドで同期的に待たないこと。
  - 方法は任意とする（例: 校正の進行は別の runspace で回し、UIスレッドは `ApplicationContext` と `Windows.Forms.Timer` で状態を取りに行く）。

#### 処理手順

0. **準備**
   - 二重実行の防止: 名前付き Mutex（`Local\PdfKoseiAssistDropReview`）を取る。取れなければ、ダイアログ「別の校正を実行中です。終わってから、もう一度『送る』を実行してください」を出して終了する。
   - ログに `drop start version=<VERSION> app=<appフォルダ>` を記録する。
   - `Repair-KoseiSendToShortcut`（§3.5）を呼ぶ。失敗しても校正は続行し、ログにだけ残す。
1. **引数の検証**
   - 0個: ダイアログで案内して終了する。
   - 3個以上: 「1回に選べるのは2ファイル（英文と日本語原稿）までです」として終了する。
   - 拡張子は `.pdf`（大文字小文字は区別しない）で、ファイルが存在すること。フォルダが渡された場合はエラーにする。
   - 同じファイルが2回渡された場合は、1個として扱う。
2. **作業フォルダの作成**
   - 場所は `Get-KoseiSubDir` で解決する実行時データの下に `drop\<32桁hexのid>\` を作る。
   - PDFを `input1.pdf` と `input2.pdf` という名前でコピーする。元のファイル名は `session.json` に保持する。
   - **サーバーへ渡すのは id だけ。** 元のファイル名は、表示名として `loadTarget` の File 名に使う（レポートや保存名に使われるため）。これは §3.4 の API 引数で渡す。
3. **サーバーの準備**
   - `settings.server_ports` を `/__health` で調べる。
   - 起動済みなら、それを使う（利用者がUIを開いていても共存できること）。
     - **ただし先に版を突き合わせる。** `/__health` の `version`（§3.7）が自分の VERSION と一致しない場合、または `version` が無い（旧版のサーバー）場合は終了する。ダイアログは「別の版のアプリが起動中です（起動中: vX / この操作: vY）。アプリ画面の『アプリを終了』で終了してから、もう一度『送る』を実行してください」。
     - 起動中のアプリを勝手に止めてはいけない。利用者が作業中の可能性がある。
     - 起動中のサーバーで校正ジョブが実行中なら、その場で終了する（§4）。
   - 起動していなければ、`Start-KoseiAssist.ps1 -NoBrowser` を非表示の別プロセスで起動し、`local-app.url` が更新されるまで最大60秒待つ。**自分で起動したかどうかを覚えておく**（後始末に使う）。
   - Copilot の準備状態（`/api/ready-state`、または `runtime\copilot-warmup.json`）が `signin_required` なら、ダイアログ「Copilot にサインインしていません。『PDF校正アシスト_初回セットアップ.cmd』を実行してサインインしてから、もう一度『送る』を実行してください」を出して終了する。
     - サーバーが返すサインイン要求（HTTP 428、`code = 'copilot_signin_required'`）の文言は「[Copilot画面を表示]から…」とUI向けに書かれている。**この経路ではそのまま表示せず、上の文言に置き換える。**
4. **アプリ画面を開く**
   - URL は `<app_url>?drop=<id>` とする。**CDP 側の Edge の新しいウィンドウ**に開く（`Target.createTarget`、`newWindow=true`）。
   - 利用者の既定ブラウザには開かない。
   - ウィンドウの表示は、既存の `browser_display_mode` 設定に従う（既定は画面外）。
   - `__koseiAutomation` が現れるまで待つ（`Wait-Hook` 相当）。あわせて `__koseiAutomation.version` が自分の VERSION と一致することを確認する。一致しない場合は、手順3と同じ文言で終了する。
   - **アプリ画面を再読み込みしてはいけない。** `beforeunload` が `/__page-closed` を送り、サーバーが止まる。
5. **対象と比較資料の割り当て**（同じフォルダに置く前提なので、質問は最小限にする）
   - 1ファイルなら、**何も聞かずに**対象として、比較資料なしで校正する。
   - 2ファイルなら、`__koseiAutomation.detectLanguage(url)` で両方の言語を判定する（§3.4）。
     - 英語と日本語の組なら、英語を対象、日本語を比較資料にする。
     - 同じ言語、または判定不能の場合は、ファイル名のヒントを見る。英文側のヒントは `_en`、`-en`、`英文`、`English`。日本語側のヒントは `_ja`、`_jp`、`-ja`、`日本語`、`和文`。
     - それでも決まらなければ、ダイアログで聞く（例: 「校正する英文は『A.pdf』ですか？」［はい］［いいえ（B.pdf が英文）］［中止］）。
   - 割り当ての結果は、開始の通知に出す。例: 「校正を始めました：A.pdf（比較資料：B.pdf）」。
   - 割り当ての規則は §6 の `drop-assignment` にある1つの実装だけにする。
6. **読み込みと開始**
   - 呼ぶ順番: `loadTarget` → （比較資料があれば）`loadReference` → `selectAllPages()` → （比較資料があれば）`autoReferenceRange()` → `startFull()`
   - どれかが失敗したら、`status().last_error` を添えてエラーのダイアログを出し、終了する。
7. **進捗の監視**
   - 5秒ごとに `status()` を取得し、`card` か `detail` が変わったらトレイのツールチップとメニューの「状況」を更新する。ログにも記録する。
   - 開始から10秒以上 `running=false` のままなら、開始失敗として扱う。
   - `needs_user_visibility` など、利用者の操作が必要な状態になった場合:
     - Copilot 用の Edge を前面に出す（`Show-KoseiCopilotEdgeWindow`）。
     - 通知で「Edge の Copilot 画面を一度クリックしてください。校正はそのまま待っています」と知らせ、待ち続ける。
   - 上限は `-TimeoutMinutes`（既定180分）とする。超えたら中止APIを呼び、ダイアログで知らせて終了する。
   - **トレイの「中止」**で `POST /api/review/cancel` を呼ぶ（空JSONボディ `{}` が必須。Content-Length が無いと411になる）。
   - どの終わり方でも、`try/finally` で後始末（手順9）を必ず行う。
8. **完了と保存（結果のフォルダ）**
   - `running=false` になったら `packets()` を取得し、失敗したパケットの数を数える。
   - `__koseiAutomation.exportReportZip("/api/drop/<id>/report")` を呼ぶ。ZIPは作業フォルダの `report.zip` に書かれる（§3.3）。このZIPは受け渡しのためだけの入れ物で、利用者には見せない。中身の構成はUIのフォルダ保存（§3.10）と同一にし、別の出力形式は作らない。
   - **指摘が0件のときも、レポートを出す。** 今の `exportHtmlReportZip` は指摘0件だとトーストを出して何もしない。そのため自動実行の経路では、0件でも「指摘なし」のレポートが作れるようにする（UIのボタンの挙動は変えない）。
   - **ZIPは保存せず、展開したフォルダを結果とする。**
     - 保存先の決め方:
       1. 対象PDFと同じフォルダに `<対象名>_校正結果` というフォルダを作る（例: `FY2027_Q1_en_校正結果`）。
          - 失敗パケットがある場合は `<対象名>_校正結果_一部未完了` にする。
          - 同名のフォルダがあれば ` (2)`、` (3)` … を付ける。**既存のフォルダには書き込まない**（前回の `_data\確認状況.json` を壊さないため）。
       2. 書き込めない場合（読み取り専用の共有フォルダなど）は、`[Environment]::GetFolderPath('MyDocuments')\PDF校正アシスト結果\` の下に同じ規則で作る。そのことを完了の通知に書く。
     - 展開は、いったん同じ親フォルダの一時フォルダ（`.<名前>.partial`）へ行い、全エントリの展開が済んでから名前を変える。途中で失敗したら、一時フォルダを消す。
     - ZIP内のファイル名には日本語が含まれる。PowerShell 5.1 の `Expand-Archive` ではなく、`System.IO.Compression.ZipFile` / `ZipArchive` で展開し、エントリ名が化けないことを確認する。
     - **エントリ名に `..` や絶対パスが含まれていたら中止する**（ZIPは自前で作ったものだが、念のため）。
   - **レポートを自動で開く**: 展開後、結果のフォルダの `_data\report-server.ps1` を §3.9 と同じ方法（窓なし）で起動し、Edge でレポートを開く。
     - 設定 `drop_open_report`（既定 `true`）で止められるようにする。`false` のときは、`explorer.exe "<結果のフォルダ>"` でフォルダを開くだけにする。
   - 完了の通知: 「校正が終わりました：指摘 N件（除外候補 M件）」。未完了パケットがあれば「一部の範囲を確認できませんでした（K件）。レポートで確認してください」を添える。
9. **後始末**
   - アプリのタブを閉じる（`Target.closeTarget`）。
   - **自分でサーバーを起動した場合だけ**、`POST /__shutdown` で止める。既に起動していたサーバー（利用者がUIを使っている）は止めない。
   - 作業フォルダは、成功時は削除する。失敗時は `drop\<id>\` を残し、エラーのダイアログにそのパスを書く（調査用）。残したフォルダは、既存の保持期間処理 `Invoke-KoseiRetentionSweep` の対象に入れる。
   - 通知が見えるよう数秒待ってから、トレイアイコンを消す（`Dispose`）。Mutex を解放する。
10. **終了コード**（ログと自動テスト用。利用者には見えない）
    - 0: 完了（未完了パケットなし）
    - 2: 完了したが未完了パケットがある（結果のフォルダは保存済み）
    - 1: エラー・中止・タイムアウト
11. **ログ**: 既存の `Write-KoseiLog` で `drop id=<id> …` という形式で記録する。**元PDFのフルパスはログに書かず、ファイル名だけにする。**

### 3.3 サーバー: `app/_app/src/Server.ps1` に `/api/drop/*` を追加

作業フォルダとの間でファイルを受け渡すためだけのAPIにする。

| メソッド・パス | 動作 |
|---|---|
| `GET /api/drop/{id}/input/{n}` | `drop\{id}\input{n}.pdf`（n は 1 か 2）を `application/pdf` で返す |
| `POST /api/drop/{id}/report` | リクエストの本文（ZIPのバイナリ）を `drop\{id}\report.zip.partial` へ**ストリームで**書き込み、完了したら `report.zip` へ名前を変える |

- `{id}` は `^[0-9a-f]{32}$` だけを受け付ける。
- `drop\{id}\session.json` がある場合だけ応答する。セッションの作成はランチャーがファイルとして直接行う（HTTP経由のセッション作成APIは作らない）。
- パスの組み立ては、固定のファイル名だけで行う。利用者由来の文字列をパスに混ぜない。
- 既存の Origin 検査（`Server.ps1` の78行付近）を必ず通す。
- **サイズ上限**: 既存の `Read-KoseiRequestBodyText` は本文をメモリに読み込む。ZIPには元PDFと比較資料がBase64で同梱されるので、200ページ級だと数十MBになる。
  - `report` だけは、専用の上限（例: 1GB）でストリームコピーする。
  - 上限は `settings` に `drop_report_max_bytes` として追加してよい（既定値は `Settings.ps1` に入れる）。
- API の一覧を `Server.ps1` 冒頭のコメントに追記する。

### 3.4 画面側: `app/_app/index.html` に `window.__koseiAutomation` を追加

- 既存の `window.__koseiBenchmark`（12237行付近）を `window.__koseiAutomation` に改名する。**互換のため、`window.__koseiBenchmark = window.__koseiAutomation` を残す**（`Run-Benchmark.ps1` とそのテストを壊さない）。
- 既存の関数（`loadTarget`、`loadReference`、`selectAllPages`、`startFull`、`status`、`packets`、`report`、`reset`）はそのまま使う。
  - `loadTarget(url, displayName)` と `loadReference(url, displayName)` は、第2引数の表示名を受け取れるように拡張する。File の name に使う。**無指定なら従来どおり URL の末尾を使う。**
- 追加するもの:
  - **`version`**: 起動時に `VERSION` を fetch して入れる（§3.7）。
  - **`detectLanguage(url)`**: PDFを取得し、pdf.js で先頭から最大5ページのテキストを、製品と同じ `extractTextLayerText` で取り出す。既存の `detectDocumentLanguage`（`js/review-settings.mjs`。戻り値は「英語」「日本語」「その他」など）で判定し、`{ language, pages, sample_chars }` を返す。
    - 画面の状態（読み込み済みのPDF・比較資料）は変えないこと。
    - pdf.js の文書は使い終わったら `destroy()` する。
  - **`autoReferenceRange()`**: 「自動入力」ボタンと同じ処理（`applyAutoReferenceRangeExplicitly(); refreshRangeFromInput(true);`、10179行付近）を呼ぶ。結果の比較資料範囲を返す。
  - **`exportReportZip(uploadPath)`**: `exportHtmlReportZip`（10070行付近）を2つに分ける。
    - **ZIPのバイト列を作る部分**: `buildHtmlReportZipBytes({ allowEmpty })` として切り出す。
    - **`downloadBlob` する部分**: UIのボタンは、従来どおりダウンロードする。
    - 自動実行では `allowEmpty: true` で作ったバイト列を、`fetch(uploadPath, { method: "POST", body: zipBytes })` で送る。
    - 戻り値: `{ ok, bytes, file_name, findings, excluded, highlight_error_count }`。`file_name` は既存の命名 `<safeFileBase>-PDF校正アシスト_HTML指摘ビューア.zip`。ランチャーはこの名前を保存名に使う。
- **起動パラメータ `?drop=<id>` の扱い**
  - この画面は通常は画面外にあって利用者には見えない。それでも、見えたときのために、上部に「自動校正の実行中です。この画面は自動で閉じます」と帯を出す。
  - 「アプリを終了」ボタンなど、ランチャーと競合する操作は無効にする。
  - **それ以外のUIの挙動は変えない。**
- **index.html は CR と LF の混在ファイル**（CRを130個含む）。編集ツールで改行を統一しないこと。
  - コミット前に `tr -cd '\r' < app/_app/index.html | wc -c` の値が変わっていないことを確認する（`grep -c $'\r'` は Git Bash だと0を返すので使えない）。

### 3.5 初回セットアップと「送る」の管理

#### 3.5.1 `app/PDF校正アシスト_初回セットアップ.cmd`（新規）と `app/_app/Setup-KoseiAssist.ps1`（新規）

- `.cmd` は `start "" powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File "%~dp0_app\Setup-KoseiAssist.ps1"` を実行して、すぐに終了する。書式は §3.1.2 と同じ規則に従う。
- **案内はすべてダイアログで出す。** コンソールには何も出さない。
- 手順:
  1. **版の確認**: 別の版のアプリが起動中なら（§3.2 手順3と同じ判定）、ダイアログで知らせて終了する。
  2. **「送る」の登録**
     - ショートカットが無ければ作る（§3.1.1 の内容）。
     - 既にある場合は、小さなダイアログで［登録し直す］［「送る」から削除する］［キャンセル］を選ばせる。
       - 「登録し直す」は、今のフォルダを指すよう作り直す。
       - 「削除する」は、ショートカットを消し、「削除しました」と知らせて終了する。サインイン確認はしない。
  3. **Copilot のサインイン確認**
     - `Start-KoseiAssist.ps1` の中にあるウォームアップ処理（`Start-KoseiCopilotEdge` → `Get-KoseiCopilotPage` → `Wait-KoseiCopilotInputReady`、`Write-KoseiWarmupStatus`）を、`src/CopilotClient.ps1` の関数 `Invoke-KoseiCopilotWarmup` に切り出す。`Start-KoseiAssist.ps1` とセットアップの両方から呼ぶ。**通常起動の挙動は変えないこと。**
     - ウォームアップの状態に応じて、次のように動く。
       - 準備ができた（`ready`）: 次へ進む。
       - サインインが必要（`signin_required`）: Copilot 用の Edge を前面に出す（`Show-KoseiCopilotEdgeWindow`）。「Edge で Microsoft 365 にサインインしてください。サインインが済むと、この画面は自動で閉じます」という小さな画面（［キャンセル］付き）を出し、`ready` になるまで最大10分待つ。
       - エラー（`error`）・時間切れ: 原因をダイアログで示して終了する。「送る」の登録はそのまま残す。
     - 終わったら、Copilot 用の Edge を既存の `browser_display_mode` の状態（既定は最小化）へ戻す。
     - アプリ（UI）が起動中の場合は、その Edge を共用する。Edge を閉じたり、起動し直したりしない。
  4. **完了の案内**: §0 の文言のダイアログを出す。
- 実行するたびに、ログへ `setup …` の形で結果を記録する。

#### 3.5.2 `app/_app/src/SendToShortcut.ps1`（新規）

- 作成・削除・自動修復の処理をまとめる。セットアップ、ランチャー、`Start-KoseiAssist.ps1` の3か所から同じ関数を呼ぶ。
- **SendTo フォルダの場所は引数で差し替えられるようにする**（テストで本物の SendTo を触らないため）。既定は `[Environment]::GetFolderPath('SendTo')`。
- ショートカットは `WScript.Shell` の COM で作る。UNC パスに展開されている場合もリンクが作れること（リンク先は UNC パスのままでよい）。
- 失敗しても例外を外に出さず、結果オブジェクトで返す。起動や校正を止めてはいけない。

#### 3.5.3 アップデート時の自動修復 `Repair-KoseiSendToShortcut`

別フォルダに新版を展開した場合でも、「送る」が旧版を指したままにならないようにする。

- **呼ぶ場所**: ランチャー（§3.2 手順0）と、通常起動の `Start-KoseiAssist.ps1`（ウォームアップ開始の前あたり）。
- **動作**:
  1. ショートカットが**無ければ何もしない**。利用者が登録していない環境に、勝手に追加しない。
  2. あれば、リンクの引数から `Start-DropReview.ps1` のパスを取り出し、その版を調べる。次のどちらかに当てはまれば、リンクを自分（今実行している版）へ張り替える。
     - リンク先が存在しない（旧フォルダが削除された）。
     - リンク先のフォルダの `_app/VERSION` が自分より古い。VERSION ファイルが無い版も、古いとみなす。
  3. リンク先の版が自分と同じか新しい場合は、変えない。旧版を起動しても、新版の登録を旧版で上書きしないため。
  4. 張り替えたときだけ、ログに `sendto repaired from=<旧版> to=<新版>` と記録する。利用者への通知はしない。
- **版の比較**: VERSION は `メジャー.マイナー[.パッチ]`（§3.7）なので、数値として各部を比較する。文字列比較はしない（`95.10` が `95.9` より新しいこと）。

#### 3.5.4 名前を変えない約束

次の名前は、**今後の版でも変えない**。変えると、アップデート後に「送る」メニューが動かなくなるか、項目が2つ並ぶ。

- ショートカット名：`PDF校正アシストで校正.lnk`
- ランチャー：`_app\Start-DropReview.ps1`（appフォルダからの相対位置を含む）
- 入口の `.cmd` 名：`PDF校正アシスト起動.cmd`、`PDF校正アシスト_初回セットアップ.cmd`

この約束は、`tools/Verify-Repo.ps1` の必須ファイルとして固定する（§3.6）。変更が必要になった場合は、自動修復で旧名のショートカットを消す移行処理を同じ PR に入れること。

    3. 別のフォルダへ展開した場合も、新版を一度使えば（起動するか、初回セットアップを実行すれば）「送る」は新版に切り替わる。
    4. 古いフォルダを消すのは、そのあとにする。
  - 「送る」から外したいときは、初回セットアップをもう一度実行して「削除する」を選ぶ。フォルダを先に消した場合は、`%APPDATA%\Microsoft\Windows\SendTo` から手で消す。
- `app/_app/README.txt`: トラブル対応に「『送る』から実行しても何も起きない」の項目を追加する（初回セットアップの再実行、ログの場所）。
- `README.md` のリポジトリ構成図に、新しいファイルを追記する。
- `docs/CHANGELOG.md` に1項目を追加する。

### 3.9 指摘レポートを窓なしで開き、閉じたら自動で終わる

レポートは、共有フォルダ上で直接開くと IE モードになる（§0）ため、同梱の `report-server.ps1`（`index.html` の `buildReportServerPs1Text`）が一時サーバーになり、`http://127.0.0.1` で開いている。今は「指摘レポートを開く.cmd」が黒い窓を出したまま動き、「見終わるまで閉じないでください」と案内している。これを、窓を出さず、レポートのタブを閉じれば自動で終わる形に変える。

**変更するもの**: `buildReportOpenCmdText` と `buildReportServerPs1Text`（`index.html` 9917〜10050行付近）、およびZIP内の説明文 `readmeText`。**#170 の修正（`/__report-state`・トークン）の上に作ること。**

1. **「指摘レポートを開く.cmd」**
   - `start "" powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -WindowStyle Hidden -File "%~dp0_data\report-server.ps1"` を実行して、**すぐに終了する**。`.cmd` の窓は一瞬で消える（`_data\` への移動は §3.10）。
   - `_data\report-server.ps1` か `指摘レポート.html` が見つからない場合（ZIPの中から直接実行した場合など）だけは、今までどおりメッセージを出して `pause` する。文言は「ZIPの中から開いています。ZIPを右クリック →『すべて展開』してから、展開したフォルダの『指摘レポートを開く.cmd』を実行してください」にする。
   - 「送る」経路（§3.2 手順8）からは `.cmd` を通さず、`_data\report-server.ps1` を同じ引数で直接、非表示で起動する。
2. **二重起動の防止（同じフォルダにサーバーは1つ）**
   - 起動時に、`_data\.report-server.json`（隠し属性。中身は `{ port, token, pid, started_at }`）を読む。
   - 記録されたサーバーが生きていて、`GET /__report-health` にトークン付きで応答すれば、**新しいサーバーは立てずに、そのURLを Edge で開いて終了する**。
   - 生きていなければ、新しく起動して `.report-server.json` を書き直す。
   - 同じフォルダで2つのサーバーが同時に `確認状況.json` を書き換える状態を作らないため。
3. **自動終了**
   - レポートの画面は、表示中は15秒ごとに `POST /__report-heartbeat`（トークン付き）を送る。タブを閉じるときは、`pagehide` で `navigator.sendBeacon('/__report-closed?t=<token>')` を送る。
   - サーバーは、次のどれかで終了し、`.report-server.json` を消す。
     - 最後のハートビートから60秒経った。
     - `closed` を受けてから10秒以内に、次のハートビートが来なかった（再読み込みや別タブで開いている場合に備える）。
     - 起動から3分経っても、最初のハートビートが一度も来なかった（Edge が開けなかった場合など）。
   - 終了前に、保存中の `確認状況.json` の書き込みが終わっていることを確認する。
   - `-NoBrowser` や `-StopAfterRequests` など、既存の引数とテストの挙動は変えない。
4. **エラーの伝え方**: サーバーの起動に失敗した場合（Edge が見つからない、ポートを開けないなど）は、窓が無いので `MessageBox` で知らせる（`-STA` で起動する）。
5. **説明文**: ZIP内の `README_使い方.txt`（`readmeText`）と「はじめにお読みください.txt」の「黒い画面は、見終わるまで閉じないでください」という記述を、「タブを閉じれば自動で終わります」に改める。
6. **UIの書き出し（§3.10）にも、同じ改良が入る。** 生成処理は1つだけなので、両方の経路で同じファイルになる。

### 3.10 レポートフォルダの構成・直接開いたときの案内・UIのフォルダ保存

#### 3.10.1 フォルダの構成を変える

今のZIPは、直下に `指摘レポート.html`、`指摘レポートを開く.cmd`、`report-server.ps1`、`指摘.json`、`指摘.csv`、`README_使い方.txt`、`assets\` が並び、どれを開けばよいか分かりにくい。次の構成に変える。

```
<対象名>_校正結果\
  指摘レポートを開く.cmd        ← 利用者が開くのはこれだけ
  指摘レポート.html

    report-server.ps1

    指摘.csv
    確認状況.json               （#170。レポートで印を付けると作られる）
    .report-server.json         （§3.9。サーバーの動作中だけ存在する隠しファイル）
    assets\                     （PDF.js・分割したPDF・CMap。今の assets\ をそのまま移す）
```

- 変更するのは、レポートの生成処理（`buildHtmlReportZipInBrowser` と、そこから呼ぶファイル一覧の組み立て、`reportHtmlDocument` 内の `assets/…` の参照パス、`cMapUrl`）と `report-server.ps1`。

- `確認状況.json` の置き場所は `_data\` にする。#170 で結果フォルダ直下に作られたものがあれば、読み込み時に `_data\` へ移す（旧版で作ったフォルダを開いても印が消えないように）。
- `.cmd` は直下に置く（利用者が開くため）。`指摘レポート.html` も、直接開かれたときに案内を出すため直下に置く（§3.10.2）。
- `Test-ReportLauncher.mjs`、`Test-ReportRender.mjs`、`Build-ReportPackageFromExport.mjs` など、今の構成を前提にしたテストと道具も合わせて直す。

#### 3.10.2 `指摘レポート.html` を直接開いたときの案内

共有フォルダ上で直接開くと IE モードになり、今は何も表示されないか、壊れた画面になる。代わりに案内を出す。

- `指摘レポート.html` の `<body>` の先頭に、**IE11 でも動く書き方（ES3/ES5。`let`・`const`・アロー関数・テンプレート文字列・`class` を使わない）の小さなインラインスクリプト**を置き、ほかのスクリプトより先に判定する。
- 次のどれかに当てはまれば、画面全体に案内を出し、レポート本体は表示しない。
  - `document.documentMode` がある（IE モード・IE）
  - `location.protocol` が `http:` でない（`file://` など）
  - `location.hostname` が `127.0.0.1` でない
- 案内の文言は「このファイルは直接開けません。同じフォルダにある『指摘レポートを開く.cmd』をダブルクリックして開いてください。ZIPの中にある場合は、先に『すべて展開』してください」。
- 案内は CSS に頼らず、`<div>` の `style` 属性で書く（IE モードでも崩れないように）。
- IE モードでない `file://`（ローカルディスクで直接開いた場合など）では、案内の下に「このまま表示する（確認済みの印は保存されません）」のリンクを出してよい。押したときだけレポート本体を読み込む。IE モードでは出さない。
- 判定のスクリプトは、Content-Security-Policy などを追加していないか確認し、今のレポートの読み込み順を壊さないこと。

#### 3.10.3 UIの書き出しをフォルダ保存にする

UIの「レポートZIPを書き出す（人に渡す用）」ボタン（`exportHtmlReportZip`、`index.html` 10070行付近）を、フォルダ保存に変える。

- ボタン名は「レポートを保存（フォルダ）」にする。
- **Edge の File System Access API（`window.showDirectoryPicker`）** で保存先の親フォルダを選んでもらう。アプリは `http://127.0.0.1` で動いているので、この API は使える。
  - `showDirectoryPicker({ id: "kosei-report", mode: "readwrite", startIn: "documents" })` とし、前回選んだ場所から始まるようにする。
  - 選んだフォルダの中に `<対象名>_校正結果` を作り、§3.10.1 の構成でファイルを書き込む。同名があれば ` (2)` … を付ける（既存のフォルダには書かない）。
  - この API ではフォルダの名前変更に頼れないため、「一時フォルダに書いてから名前を変える」方式は使わない。書き込みの途中で失敗した場合は、作りかけのフォルダを削除（`removeEntry(name, { recursive: true })`）してからエラーを出す。
  - 保存後は「『<親フォルダ名>\<結果フォルダ名>』に保存しました。フォルダ内の『指摘レポートを開く.cmd』で開けます」と表示する。
  - 利用者がフォルダ選択をキャンセルした場合は、何もしない。
- **`showDirectoryPicker` が無い環境（Edge 以外のブラウザや、ポリシーで無効な場合）だけ、従来どおりZIPをダウンロードする。** その場合はボタン名とメッセージで「ZIPで保存しました。『すべて展開』してから、中の『指摘レポートを開く.cmd』を実行してください」と伝える。ZIPの中身も §3.10.1 の構成にする。
- レポートの中身を作る処理は、「送る」経路（§3.4 の `buildHtmlReportZipBytes`）と共有する。ファイル一覧（名前とバイト列）を作る関数を1つにし、ZIPにまとめるか、フォルダに書くかだけを分ける。
- UIの「その他の保存」（補助PDF・JSON・CSV）は変えない。

## 5. 受け入れ基準

実機（Copilot にサインイン済みの開発機）で、次がすべて満たされること。検証手順はメモリの実機検証手順と同じで、テスト用PDFは `app/_app/docs/benchmarks/` にある。

**「送る」経路（正式）**

1. `docs/benchmarks/real/mazda_fy2027_q1_financial_results_en.pdf` と `_ja.pdf`（取得方法は同フォルダの README を参照）を同じフォルダに置き、2つを選んで「送る」から実行する。
   - **黒い窓とアプリ画面が、利用者の目に触れないこと**（起動の瞬間にタスクバーでちらつく程度は可）。
   - トレイアイコンが出て、進捗がツールチップで追えること。
   - 英文が対象、日本語が比較資料に割り当てられること。_ja 側を右クリックして送った場合（引数の順番が逆になる）も同じ割り当てになること。
   - 完了後、英文PDFと同じフォルダに `<対象名>_校正結果` フォルダができ、**Edge で指摘レポートが自動で開く**こと。
   - 結果のフォルダの中身が、同じ2ファイルをUIで「校正を開始」→「レポートZIPを書き出す」したZIPを展開したものと**同じ仕組みの出力**であること。件数は Copilot の揺らぎがあるので一致しなくてよいが、JSON のスキーマ・ファイル構成が同一であること。
2. 英文PDFを1つだけ送ると、何も聞かれずに比較資料なしで完了し、結果のフォルダが保存されてレポートが開くこと。
3. 次のパスで、1が成功すること。
   - 空白を含むパス
   - 日本語を含むパス
   - `&` を含むパス
   - `%` を含むパス
   - `(1)` を含むパス
   - UNC パス（`\\localhost\c$\...` など）
4. 実行中にトレイの「中止」を選ぶと、確認のあと中止APIが呼ばれ、Copilot 側のジョブが止まること（ログに `ジョブ終了 … mode=cancelled`）。トレイアイコンが消え、プロセスが残らないこと。
5. 実行中にもう一度「送る」を実行すると、§4 の文言ですぐ終わり、実行中の校正に影響しないこと。
6. 指摘0件の文書でも、「指摘なし」のレポートが保存されて開くこと。
7. 同名の結果フォルダが既にあるとき、既存のフォルダ（とその中の `確認状況.json`）に手を付けず、` (2)` 付きのフォルダに保存されること。
8. トレイのメニューが、校正の実行中も2秒以内に反応すること。

**レポートの開き方（§3.9）**

8a. 自動で開いたレポートで「確認済み」を付けてタブを閉じると、60秒以内に一時サーバーのプロセスが終わり、`.report-server.json` が消えること。
8b. 結果のフォルダの「指摘レポートを開く.cmd」をダブルクリックすると、**黒い窓が残らずに**レポートが開き、8a で付けた印が表示されること。
8c. レポートを開いたまま、もう一度「指摘レポートを開く.cmd」を実行すると、一時サーバーは増えずに（プロセスが1つのまま）、同じレポートが開くこと。

8f. 設定 `drop_open_report=false` では、レポートは開かず、結果のフォルダがエクスプローラーで開くこと。

**レポートフォルダ（§3.10）**

8g. 結果のフォルダの直下が、`指摘レポートを開く.cmd`・`指摘レポート.html`・`_data\` の3つだけであること。印を付けると `_data\確認状況.json` ができること。

8j. #170 の版で作った結果フォルダ（直下に `確認状況.json` がある）を新しい「指摘レポートを開く.cmd」で開くと、印が引き継がれ、`_data\` へ移ること。
8k. UIの「レポートを保存（フォルダ）」で、選んだフォルダの下に §3.10.1 の構成のフォルダができ、その `.cmd` でレポートが開くこと。同名のフォルダがあれば ` (2)` 付きになること。フォルダ選択をキャンセルすると、何も起きないこと。
8l. `showDirectoryPicker` を無効にした状態（テスト用に `window.showDirectoryPicker` を消すなど）では、ZIPのダウンロードに切り替わり、その旨が表示されること。

**UIとの共存**

9. UIで作業中（サーバー起動済み、ジョブなし）に「送る」を実行しても成功すること。完了後も**UIのサーバーが止まらない**こと。
10. UIで校正が実行中のときに「送る」を実行すると、§4 の文言ですぐ終了し、UI側のジョブに影響しないこと。

**初回セットアップ**

15. 「送る」未登録・サインイン済みの環境で実行すると、登録されて完了の案内が出ること。コンソールが表示されないこと。

18. サインインしていない状態で「送る」を実行すると、初回セットアップを促すダイアログが出ること。

**アップデート**

19. **上書き更新**：旧版のフォルダで登録し、VERSION だけを上げた新版を同じフォルダへ上書き展開する。「送る」から実行すると新版で動くこと（ログの `drop start version=` で確認）。
20. **別フォルダへの更新**：旧版のフォルダ A で登録し、新版をフォルダ B に展開する。
    - B の通常起動（または初回セットアップ）を1回実行すると、ショートカットが B を指すようになること。
    - そのあと A の通常起動を実行しても、ショートカットは B のままであること（旧版で上書きしない）。
    - A を削除した状態で、ショートカットが A を指していても、B を起動すれば修復されること。
21. **未登録の環境**：「送る」を登録していない環境で通常起動を実行しても、ショートカットが作られないこと。
22. **新旧の混在**：旧版（`/__health` に `version` が無い版を含む）のアプリを起動したまま新版の「送る」を実行すると、§4 の文言ですぐ終了し、旧版のアプリも動き続けること。

**配布**

24. `tools/Package-Release.ps1` で作ったZIPを新しいフォルダへ展開し、初回セットアップ →「送る」で 1 が通ること。配布フォルダ直下の起動用ファイルが、`.cmd` の「起動」と「初回セットアップ」の2つだけであること（`.vbs` が含まれないこと）。

## 8. 注意点（既知の落とし穴）

- **レポートは一時サーバー経由で開く。** 共有フォルダ上の HTML を直接開くと IE モードになる社内環境がある（§0）。「HTMLを1ファイルにして直接開く」「`file://` で開く」方向の簡略化はしないこと。
- **アプリ画面は再読み込みしない。** `beforeunload` → `/__page-closed` → サーバーの停止、となる（`__koseiBenchmark.reset()` のコメントを参照）。
- **画面は表示状態に保つ。** アプリのタブや Copilot のタブが非表示（`document.hidden`）だと、パケット作成や回答の読み取りが止まることがある（`Run-Benchmark.ps1` の `Show-AppTab`、`Get-CopilotVisibility` を参照）。画面外に配置するのはよいが、最小化で `visibilityState=hidden` にならないか、実機で確認すること。
- **Copilot のウォームアップを待つ。** `POST /api/review/jobs` は、ウォームアップ中なら最大120秒待つ。未サインインなら HTTP 428 を返す。文言は §3.2 手順3のとおり置き換える。
- **中止APIは空JSONボディ必須。** `POST /api/review/cancel` は、Content-Length が無いと411になる。
- **非表示の PowerShell では、コンソール入力ができない。** `Read-Host` やコンソールでの確認は使わない（黙って固まる）。WinForms を使うため `-STA` で起動する。
- **`NotifyIcon.Text` は63文字まで。** .NET Framework では、超えると `ArgumentOutOfRangeException` になる。
- **トレイアイコンの後始末。** 異常終了でも `Dispose` しないと、マウスを乗せるまで通知領域に幽霊アイコンが残る。`finally` で必ず消す。
- **`Verify-Repo.ps1` の既知のFAIL。** 実行時生成物（`local-app.pid` など）が存在するだけで FAIL する。開発機では既知の4件は無視してよい。
- **`.cmd` の文字コード。** UTF-8（BOMなし）かつ CRLF にする。`.gitattributes` は改行・エンコーディングの変換を全面禁止しているので、エディタの自動変換に注意する。ZIP に入れるときのファイル名 UTF-8 フラグは `Package-Release.ps1` が面倒を見る。
- **名前と位置は変えない。** ショートカット名・ランチャーの位置・入口の `.cmd` 名は、アップデート後も「送る」が動き続けるための約束（§3.5.4）。リファクタリングのついでに変えないこと。
- **本物の SendTo をテストで触らない。** 開発機の `%APPDATA%\Microsoft\Windows\SendTo` にテスト用のショートカットを作ったり消したりしない。
- **マスキング・プライバシー。** Copilot へ送る内容はUIと同一経路なので変わらない。新たに外部へ送るものは無い。作業フォルダのPDFコピーは、成功時にすぐ削除する。ログには元PDFのフルパスを書かない。
