
## 2. 決めたこと（と、その根拠）

| 決めたこと | 根拠（すべて実測） |
|---|---|
| **幅は分割しない**（全文1セクション） | 広げるほど実検出数は増え、ターン数は減る。距離110/130 でも取れる。効くのは距離ではなく「同じ窓に入っているか」 |
| **観点を分ける** | 1ターンに詰め込むと出力の枠を数値の照合が食い切り、表記の揺れが 2/24 に落ちる。分けると 17/24 に戻る |
| **観点は並列**（追撃ではなくパケット） | terms / numbers / structure は既出一覧に依存しない＝前のターンに依存しない。ワーカー4本にそのまま乗る |
| **2ラウンド** | 取りこぼしは同じ場所に固定されない（term 24件中17件が構成で出たり出なかったり）。穴は注意の配分 |
| **ラウンド2は探し方を変える** | 同じ指示だと同じものが見つかり、報告禁止リストに弾かれて**0件になる**。手順を変えると 0件 → 4〜6件 |
| **会計連動は廃止** | マスクした状態では記号を足すことになり原理的に不可能（全幅で 0/6） |
| **`needs_human_review` は整合性で使わない** | REFなしでは半分以上に付き旗として機能しない。外すと strict 42% → 76.8% |
| **drift（訳語の揺れ）は担当外** | 原文が同じことを知らないと判定できない。整合性はREFなし、校正は10pで跨げない。**どちらも担当しない** |

## 5. 踏んだ罠（ここが一番の資産）

**同じ穴に落ちないために、必ず目を通すこと。** どれも「静かに壊れて、数字だけが変わる」型。

1. **表の裸のセルが本文と別記号になる**
   財務諸表は単位を行の見出しに書く。素直に読むと表の `458,921` と本文の `458,921 million yen` が
   別の実量になり、Copilot が「P.6 と P.22 の売上高が一致しない」と6件報告した。
   モデル側では見抜けない型。行単位の単位継承で解決。

2. **画面が古いコードのまま走る**
   `Reset-App` は仕様上ページを読み込み直さない（読み込むとサーバーが止まる）。
   マスカーを直した直後の run が直す前の挙動で走り、5分を捨てた。
   → `loadedAt` と `Assert-FreshPage` で中止するようにした。**コードを直したらアプリを再起動**。

3. **観点パケットが同じ添付ファイル名を使うと落ちる**
   同じジョブディレクトリの同じ名前へ同時に書き、「添付完了を80秒以内に確認できませんでした」。
   落ち方が静かで、結果は「その観点は何も出さなかった」に見える（term 0/24 の正体）。

4. **ラウンド2で同じ指示を出すと0件になる**
   同じ探し方をすれば同じものが見つかり、それは報告禁止リストに載っている。
   **手順を変える**こと（numbers は「指標名を列挙してから記号を突き合わせる」に変更）。

5. **既出一覧をそのまま渡すとマスキングが無意味になる**
   画面の findings は記号を実値へ戻した後の姿。**マスクし直してから**渡す。伏せきれなければ渡さない。

6. **観点の指示に素材の答えを書いてしまう**
   `terms` の例に planted 4件をそのまま書いていた。その4件は 4/4、例に無い20件は 17/20。
   term 87.5% は**答えを見せた状態の数字**だった（消したら 75%）。
   → `Test-ConsistencyLenses.mjs` が gold の断片158個と照合して止める。

7. **`Test-IndexHtmlSyntax` が致命的な構文エラーを見逃していた**
   (a) 正規表現で綴じタグまで切ると、本体の巨大なテンプレート文字列の内側から始まる断片が取れ、
   何を入れても構文エラーにならない → **行で切る**。
   (b) 一時ファイルが `.js` だと CJS として包まれ V8 が関数本体を遅延解析する → **`.mjs`**。
   この2つのせいで、文字列に生の改行が入ってアプリが真っ白になったのに PASS と報告していた。

8. **フィクスチャ側の欠陥をモデルが正しく指摘する**
   目次のページ番号が架空の値で、実際の開始ページと食い違っていた（4件が「誤検知」に計上された）。
   実ページを埋めるようにした。**誤検知を疑う前に、まず素材を疑う。**

9. **`taskkill /IM msedge.exe` は利用者のブラウザまで巻き込む**（PID指定にすること）

11. **gold の `packet_id` を間違えると、当たっていても recall 0% と出る**（2026-08-06）
    `report-to-run.mjs` は run の全指摘を1つの `packet_id: "ALL"` にまとめる。
    自作の gold を `"SEC_001"` にしていたら突き合わせ相手が空になり、
    **4件当たっているのに 0/7** と表示された。指摘の中身を見るまで
    「実物では全く取れない」と読むところだった。**採点が0%なら、まず突き合わせを疑う。**

10. **ワーカー用のEdgeウィンドウを作りっぱなしにしていた**（2026-08-05 21:40 修正）
    `New-KoseiCopilotWorkerPages` は `newWindow=$true` で（ワーカー数−1）個の**別ウィンドウ**を作るのに、
    `Target.closeTarget` がコードのどこにも無かった。**レビュー1回ごとに3個増える**。
    ベンチマークを6本回した時点で専用プロファイルのウィンドウが**32個**・`msedge.exe` が**62プロセス**になり、
    利用者からは「アプリを使うほど画面が増える」に見えた。機能は正常に動くので気づけない型。
    → `Close-KoseiCopilotWorkerPages` を追加し、ジョブの正常終了・中止・致命エラーの全経路で呼ぶ。
    作る側も途中失敗時に自分の作った窓を閉じてから投げ直す。`Test-WorkerPageCleanup.mjs` が対で呼ぶことを縛る。
    **数え方の注意**: CDP の `/json` は入れ子配列を返すので素直に数えると4倍に見える
    （32枚が124枚に見えた）。`Get-KoseiCdpTargets` と同じ平坦化を通してから数えること。

## 7.5 追記（同日 21:20 / 残タスク#1「複数run」を実施した結果）

推奨構成を**3回**回した。§1の数字（recall 82.1% / precision 98%）は**中央値としてそのまま通る**が、
やってみて分かったことが3つある。詳細は `docs/benchmarks/README.md` の【確定】節。

1. **`needs_human_review` の廃止が中途半端だった**（新しい罠。§5に足すならこれが10番目）
   整合性プロンプトは「needs_human_review の区別は使いません。指定しないでください」と
   書いておきながら、**直下の出力JSONひな型に `"needs_human_review": true` が残っていた**。
   モデルはひな型を写すので、写した run では 47件中37件に旗が付き、写さなかった run では 50件中7件。
   採点側はこの旗で findings と uncertain_candidates を分けるため、**同じ構成なのに
   strict が 12.5% と 76.8% に割れた**（assisted は 75 / 82.1 で正常）。
   → ひな型から削除。`Test-ConsistencyLenses.mjs` に「指示文とひな型が食い違っていないか」を追加。
   **旗の数は run ごとに確認すること**（0件でなければ何かが復活している）。
   §2の表にある「外すと strict 42% → 76.8%」は、**たまたまひな型を無視した1回**の数字だった。

2. **clean な4回（旗0件・strict = assisted）**

   | run | recall | precision | number | term | structure | structure-local |
   |---|---|---|---|---|---|---|
   | 2107 | 83.9 | 94.2 | 17/24 | 22/24 | 4/4 | 2/2 |
   | 2112 | 80.4 | 98 | 18/24 | 19/24 | 4/4 | 2/2 |
   | 2120 | 82.1 | 98.2 | 18/24 | 21/24 | 4/4 | 1/2 |
   | 2141 | 76.8 | 96.4 | 17/24 | 18/24 | 4/4 | 2/2 |
   | **中央値** | **81.3** | **97.2** | **17.5/24** | **20/24** | **4/4** | 2/2 |

   全体の recall は 43〜47/56（**幅4件**）。**観点別のほうがよく振れる**（term は 18〜22件）。
   §1に書いた「number 21/24・term 18/24」はどちらも1回の値。
   **1回の測定で1〜4件の差を語らないこと。**

3. **残タスク#2「`structure-local` が毎回 1/2」は誤り**
   6本中 1/2 が3本・2/2 が3本。分母2件の計器なので行き来する。
   校正パケット側で拾うかどうかを考える前に、**素材の件数を増やすのが先**。

## 7.6 追記（同日 21:55 / 残タスク#6「`omitted_uncertain_findings`」）

**誰も読んでいなかった。** モデルが「根拠を確認できないので報告しなかった件数」を返しても、
`importResponse` は素通りさせて捨てていた。さらに整合性側は、この箱の使い方を書いた指示が
**1行も無い**（説明は校正パケット側の `buildPacketPromptText` にしかない）のに、
出力ひな型には欄だけあった — 罠#10 と同じ「指示文とひな型の食い違い」型。

| | 整合性パケット | 校正パケット |
|---|---|---|
| `needs_human_review` | 使わない（指示・ひな型とも削除） | 従来どおり使う（REFがあるので旗が機能する） |
| `omitted_uncertain_findings` | **箱ごと削除** | 残す（推測させないための弁）。**件数を取り込み時に画面へ出す** |

整合性から外した理由は、このモードが「この節の指摘はすべて要確認候補」と宣言していること。
そう言ったうえで「確信が持てないものを入れる箱」を渡すのは、recall で測っている側から見れば
**黙って落としてよい置き場**を渡すのと同じになる。
校正側に件数を出すようにしたのは、0件回答が「本当に無かった」のか
「根拠を確認できず出せなかった」のかを区別できないままだったため。

修正後の実測1回（`-2155`）: **recall 80.4% / precision 100%**（誤検知0・旗0件）。
4回の幅（76.8〜83.9%）の中で、悪化は出ていない。ただし**1回では小さな変化は検出できない**。

| | 合成フィクスチャ 200p | 実物 167p |
|---|---|---|
| 整合性レビュー | recall 83.3% / precision 96.9% | **送信中止（0指摘）** |

| `(Notes ⟦#FTS⟧,5)` | `(Notes 4,5)` |

### 素材を v2 にした（残タスク#2'）

版が違う run は分母が違うので比較してはいけない。`score-runs.mjs` が採点時に版を表示する。

## 7.8 追記（同日 23:10 / 残タスク#8「マスカーを実物で通す」を実装）

**実物が通るようになった。**

| | 実装前 | 実装後 |
|---|---|---|
| 実物 167p のマスキング | 伏せ損ね **42件** → 送信中止 | **0件** → 送信できる |
| 実物の整合性レビュー | 0指摘（送信されていない） | 4パケットとも回答・**指摘0件** |

実物の0指摘は「モデルが167ページ全部を確認したうえで、断定できる跨ぎ不整合は無かった」
という回答（`reviewed_target_page_count: 167` / `read_error` なし / `no_findings_reason` あり）。
公表済みの監査済み文書なので0件はありうるが、**実物には正解が無いので0件が正しいかは判定できない**。
確かめるなら実物に既知の誤りを埋めた版が要る（未着手）。

### 直したのは4か所（`js/number-mask.mjs`）

1. **注記参照の番号列を塊として残す**（規則1・2）。`(Notes 4,5)` `*2,6` `16,17`。
   カンマの後ろが3桁でない数字の並びは**桁区切りではありえない**ので、金額と区別できる。
2. **桁区切りの直後に数字が続いてはいけない**（`(?!\d)`）。実物 p126 の `September 30,2024`
   （カンマ後の空白なし）で `30,202` を食い、`4` が平文で残っていた。
3. **単位の継承を行から表ブロックへ**（規則5・6）。単位行から下へ、空行・ページ跨ぎ・
   数字の無い行が2行続くまで。
4. **検証器の部分マスク検出にカンマ＋1〜2桁を追加**（規則3）。

### 実装して分かった、仕様の訂正2つ

§4.2c に書き足した。**どちらも「原因の見立てが外れていた」型**なので、目を通すこと。

- **規則4の原因は日付パターンではなくトークナイザだった。** 「月日を最長一致で」と書いたが、
  実際は桁区切りの貪欲一致。日付固有の細工は要らなかった。
- **散文の見分けは「文らしさ」では足りない。** 「20語以上で句点終わり」を目印にしたら、
  15語の英文と、**空白が無いので1語に見える日本語**が2回すり抜けた。
  「表の行らしさ」（文末で終わらない・数値が複数・短い）で判定する形に変えた。
  文字数の上限は言語で分ける（英語60・日本語30）。英語の表の行はラベルが長い。

`Test-NumberMask.mjs` に §4.2c のテストを10件足した。実物PDFはコミットしていないので、
**壊れ戻りを止めるのはこのテストだけ**。実物での再確認は `node tools/Audit-DocumentMask.mjs <pdf>`。

### 合成フィクスチャ側の回帰（現行コードの最新値）

素材v2＋マスカー修正後を3回。**これが最新の数字**（`docs/benchmarks/README.md` の v2 節）。

| | 中央値 | 3回の幅 |
|---|---|---|
| recall | **75.8%**（50/66） | 71.2 〜 83.3% |
| precision | **93.2%** | 92.1 〜 96.2% |
| number | 16/24 | **15〜22件（振れが大きい）** |
| term | 19/24 | 19〜21件 |
| structure | 6/8 | 6〜8件 |
| structure-local | 5/8 | 4〜5件 |

**マスカー修正の前後は比べられない。** 修正前の v2 実測は1回（83.3%）で、修正後3回の幅の中にある。
計器の不変条件（同じ実量に同じ記号・日英で記号が揃う）は `Test-FixtureTextLayer` が通っているので、
跨ぎ比較の土台は保たれている。

分母を増やして見えたこと（v1 では分からなかった）:

- `structure`（跨ぎ）の「4回とも 4/4」は**天井に張り付いていただけ**だった。分母8件では 6〜8件。
- `structure-local` は 62.5% 前後。**同一ページの番号の乱れは弱い**、と分母8件で初めて言える。
- `number` の振れが 15〜22件と大きい。v1 の「17〜18件で安定」は4回とも似た結果を引いただけの
  可能性がある。ここは回数を増やして測り直す価値がある。

## 7.9 追記（2026-08-06 / 残タスク#9「実物に既知の誤りを埋めた版」）

**実物でも動く。** 原本のページは1文字も変えず、末尾に補足ページを足して誤りを8件埋めた
（`docs/benchmarks/real/plant-real-errors.mjs`）。

| | 結果 |
|---|---|
| planted の検出 | **4/7 = 57.1%** |
| 観点別 | number **2/2** / structure **2/2** / term **0/2** / structure-local **0/1** |
| 対照群（正しい値を再掲） | 指摘なし＝正しい |

**合成フィクスチャと同じ弱点が実物でも出た**（term と structure-local が弱い）。
素材が変わっても同じ観点が落ちるので、これは素材の作りではなく**観点の実力**である。

### いちばん大事なこと: 原本の実在の不整合を4件見つけた

planted 以外の4件は、機械的には誤検知に数えられて precision 50% と表示された。
**全部を原本と照合したら、4件とも本物だった。**

| 指摘 | 原本での確認 |
|---|---|
| 中国子会社の旧社名に `(China)` の有無 | p40 に `(China)` あり / p7 に無し |
| `Pharmaceutical` / `Pharmaceuticals` Business | p9 は複数形、p37 のセグメント表は単数形 |
| 労働組合名が2通り | p9 の31行と34行で別の名前 |
| `Co, Ltd.` のピリオド欠落 | p23 の同じ行に `Co, Ltd.` と `Co., Ltd.` が並存 |

**実物では precision を測れない。** gold は原本にもともと有る不整合を知らない。
`gold-real.json` に `precision_measurable: false` を持たせ、`score-runs.mjs` は
precision を「測れない」と表示する。数字が独り歩きするより空欄のほうがよい。

> 原本のまま（誤りを埋めない版）は0指摘だった。同じ文書で、埋めた版では上の4件を見つけている。
> **0指摘は「この文書に何も無い」ことを意味しない。** §7.8 の0指摘はそう読むこと。

### 踏んだ罠（#11）: gold の `packet_id` を間違えると、当たっていても 0% と出る

`report-to-run.mjs` は run の全指摘を1つの `packet_id: "ALL"` にまとめる。
gold 側を `"SEC_001"` にしていたため突き合わせ相手が空になり、**4件当たっているのに
recall 0/7 と表示された**。指摘の中身を見るまで「実物では全く取れない」と読むところだった。
合成フィクスチャの gold も `"ALL"` になっている。**採点が0%のときは、まず突き合わせを疑う。**
